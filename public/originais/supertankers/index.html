How the harbour works

Every berth is an app that sends requests to AI models through OpenRouter. Every vessel is one request, and it carries what that request sends the model: one container for every 2,000 tokens. A chat message carries the recent conversation; a coding agent carries the whole project again on every turn. So chat comes in tugboats and agents in freighters.

Size by

Same cargo: every berth unloads the same freight, as much as one request from the app with the biggest requests. Count the trips each app needs to deliver it. Requests: each berth's fleet is its real weekly traffic, one vessel for every 8 million requests (a faint hull is the part of a vessel left over). Per request: one vessel each, side by side.

The chips choose which apps get berths: the default compares a chat app with a coding agent that sends about as many requests, then the busiest agents and the app with the biggest requests.

What is exact and what is not

Requests, tokens and tokens per request are this week's real totals. The container count is tokens per request divided by 2,000 and rounded up, so a vessel is exact to within one container. Fleet counts in Requests mode are scaled to fit a berth (the scale is stated above). Tokens are counted by each provider's own tokenizer. The harbour fee is the median cost of one session in the four agents OpenRouter publishes session costs for.
